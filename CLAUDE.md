# Claude Code workflow

These are Ahamed's standing engineering conventions for this repository. Read the existing README and CONTRIBUTING.md (if present) before editing. Apply these rules to every task, not just the current conversation.

## Git identity and commits

- For new work directed by repository owner Ahamed, configure Git author `Ahamed Mohamed Wajibu <91502527+amw720386@users.noreply.github.com>` and add the standalone trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` to Claude-written commits. If preserving a Claude-authored commit, keep its original author and add `Co-Authored-By: Ahamed Mohamed Wajibu <91502527+amw720386@users.noreply.github.com>` where Ahamed directed that work. Never rewrite another person's authorship or claim credit for unrelated human contributions.
- Use short, precise Conventional Commit subjects: `feat(scope): ...`, `fix(scope): ...`, `perf(scope): ...`, `test(scope): ...`, `docs(scope): ...`, `chore(scope): ...`. Keep one logical change per commit. Do not put session URLs, long bullet lists, or autogenerated clutter in the subject.
- Use readable topic branches such as `feat/vmm`, `fix/nvrtc-fp16`, or `perf/decoder-latency`. When the platform gives an internal `claude/<random>` branch, preserve the work but publish the PR from a semantic branch if safely possible.

## Pull requests and quality

- Never push directly to protected `main` or another protected integration branch. Inspect the repository's current default/integration branch before opening a focused PR.
- A meaningful change is not finished when code compiles: run relevant tests, reproduce bugs, provide exact commands and actual results, and disclose anything not tested. Do not claim GPU validation from a CPU-only/cloud machine. Never silently substitute a different backend for a claimed CUDA result.
- Create the PR yourself, fix identified problems, and merge after required tests and reviews pass and repository protections permit it. If blocked, identify the exact error and a reproducible next step; continue useful unblocked work.
- No GitHub Actions or paid CI without explicit authorization. Respect each project's spending cap. Do not create `AGENTS.md` or unnecessary reports, generated outputs, branches, or filler files.

## Safe historical repair and cleanup

- For previously uncredited agent-owned commits, inspect commit history and PR dependencies before rewriting. Preserve unrelated/third-party commits verbatim. Back up the old ref, record SHA mappings, and use `--force-with-lease` only on a verified agent-owned, unprotected branch where a rewrite will not discard someone else's work. Never force-push `main`, shared/merged history, or another contributor's branch.
- Remove stale generated artifacts or temporary branches only after confirming exact targets and that the underlying work and evidence remain recoverable.
- Prefer direct engineering and validation over planning-only responses. After a verified milestone, choose the next highest-impact remaining task within the existing authorization and budget. Stop for real blockers, not routine tooling friction.
